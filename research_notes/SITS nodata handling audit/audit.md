# How open-source SITS crop-classification code handles missing and cloudy observations

Audit date: 2026-10-28. Each repository was shallow-cloned at its default branch, and the code was read directly. The commit hashes are in the evidence links. Line numbers refer to those commits. Nothing was executed. Where I could not trace a behaviour in code, the note says "not verified".

## Summary

I audited 17 codebases (16 repositories plus `prometheo`, the model library that WorldCereal depends on, which is counted together with WorldCereal). The verdicts break down as follows. Four use **consistent masking**: missing or padded steps are flagged to the model in training and inference (SITS-BERT, U-TAE, WorldCereal/prometheo, EuroCropsML). Three use a **consistent in-distribution fill**, meaning linear interpolation or extrapolation onto a regular grid that runs identically in training and prediction (R `sits`, eo-learn, Sen4AgriNet/S4A-Models). Three rely on **upstream compositing that hides gaps**: an Earth Engine cloud-score quality mosaic per 30-day step, with leftover NaNs filled by a data-derived mean (Presto, CropHarvest, OpenMapFlow). Five have **no gap handling**: cloudy observations stay in the series as raw values, or invalid rows are dropped from an irregular sequence (BreizhCrops, PSE-TAE, L-TAE, TimeMatch, AI4Food starter pack). One uses a **zero/constant fill without a mask, but consistently and with padding present in training** (TSViT/DeepSatModels), so it is not the failure mode. One is **not applicable** because it is only a dataset loader (torchgeo PASTIS). Two candidates were not audited: MCTNet, and the code for Che et al. 2024.

No audited repository shows the specific failure mode: a constant written into a month that is almost always observed in training, applied only at inference, before a training-fitted scaler. The closest cases are edge paths. OpenMapFlow fills a band that is all-NaN in a tile with raw 0 before normalization. TSViT and U-TAE pad with 0 after normalization, which equals the training mean. In TSViT the model is not told the step is padding. Two classes are vulnerable in principle: fixed-grid pipelines that interpolate (they are robust to this failure as long as interpolation also runs at inference, which it does in all three), and irregular-sequence pipelines (a missing date simply drops out). The evidence therefore does not support a claim that zero-fill-at-inference is common in *public reference code*. It does support a weaker claim. Most public code avoids constant fills by compositing, interpolation or masking, so a practitioner who builds a fixed monthly grid by hand, as our pipeline did, is outside the path these codebases protect. Only one codebase (WorldCereal) simulates missing timesteps during supervised training. Presto does so only during self-supervised pretraining, and TimeMatch and BreizhCrops randomly subsample dates.

## Per-repository notes

**BreizhCrops (dl4sits/BreizhCrops).** `BreizhCrops.load` drops every time step that has a NaN in any band (lines 257-259). `get_default_transform` (lines 339-366) scales reflectance by 1e-4 and draws 45 indices with `np.random.choice`, with replacement when the parcel has fewer than 45 observations. This runs at evaluation time as well. The model gets no acquisition dates, so a missing date never becomes a filled value. A short series becomes duplicated real observations. Cloudy acquisitions are not filtered in the dataset code: the L1C data carries clouds as raw values. The `PADDING_VALUE` code is commented out (lines 296-297, 341, 353). Verdict: no constant fill, and no cloud handling.

**PSE-TAE (VSainteuf/pytorch-psetae).** Every parcel shares one `dates.json` (dataset.py lines 70-73), so the temporal axis is fixed and identical in training and test. The only nodata logic is spatial. `dataset_preparation.py` line 68 clips polygons with `nodata=uint16 max` and removes those pixels. Zero padding of the pixel set is tracked by a pixel mask (lines 104-123, 145). Normalization uses a precomputed mean/std (lines 125-138). The code contains no cloud masking. I did not verify from the code whether cloudy dates were excluded when S2-Agri was built.

**L-TAE (VSainteuf/lightweight-temporal-attention-pytorch).** `dataset.py` is the same pixel-set loader as PSE-TAE (same line ranges), with no temporal missingness handling.

**U-TAE (VSainteuf/utae-paps).** PASTIS patches have their own variable-length date sequences. The dataset normalizes in `__getitem__` (dataset.py lines 179-182). `pad_collate` then pads the temporal axis with `pad_value`, which defaults to 0 (`train_semantic.py` line 94, utils.py lines 11-29). Padding therefore happens after normalization. The model rebuilds `pad_mask` from frames that equal `pad_value` everywhere (utae.py lines 133-134). L-TAE masks those frames out of attention (ltae.py line 206, `masked_fill(..., -1e3)`). Training and inference use the same collate function. The repo does no cloud filtering.

**TimeMatch (jnyborg/timematch).** The default collection is L1C (`prepare_pixels.py` line 323). Tiles are kept up to `max_cloudy_percentage=80` (line 318), and cloudy pixels are left in the data. For L2A, a rasterized cloud mask is appended as an extra band (lines 80-81, 158-180), but models default to `input_dim=10` (train.py line 293). I did not verify whether the extra band is ever consumed. `RandomSampleTimeSteps(30)` subsamples dates during training (train.py line 135). At test time it runs only for `tsnet` (dataset.py lines 211, 234). Each parcel keeps its tile's acquisition dates as positions.

**SITS-BERT (linlei1214/SITS-BERT).** According to the README (lines 72-73), observations labelled cloud, cirrus, shadow or snow by the SCL map were discarded before the CSVs were made. `finetune_dataset.py` lines 36-45 zero-pad the reflectance to `seq_len` and set `bert_mask[:ts_length]=1`. DOY is passed per observation. Pretraining (`pretrain_dataset.py` lines 59-76) adds noise to random observations and does not remove them.

**Presto (nasaharvest/presto).** Earth Engine export goes through openmapflow's `create_ee_image`, which builds a `qualityMosaic("cloudShadowScore")` per 30-day step (see OpenMapFlow). The mosaic always yields a value when any image exists. `convert_tif_to_np` calls `load_tif(fillna=True)` (`s1_s2_era5_srtm.py` lines 114-118). `construct_single_presto_input` (utils.py lines 55-93) zero-fills absent band groups, sets mask=1 for them, and normalizes. The mask removes tokens from the encoder. Pretraining includes `random_timesteps` and `chunk_timesteps` masking strategies (masking.py lines 17-22). So the architecture could take a missing-month mask, but Presto's own pipeline fills missing values upstream and does not flag them.

**CropHarvest (nasaharvest/cropharvest).** Uses the same EE quality mosaic (`eo/sentinel2.py` lines 187-188). `Engineer.fillna` (engineer.py lines 335-366) replaces NaNs with the band's mean over that pixel's time series. It returns `None`, which drops the sample, if a whole band other than slope is NaN. The fill runs on raw values before normalization, both for training files (line 490) and for test files (`process_test_file`, line 409).

**OpenMapFlow (nasaharvest/openmapflow).** The 30-day timesteps come from `bands.py` line 61, with the EE quality mosaic in `eo/sentinel2.py` lines 46-57 and 202-203. `_fillna` (engineer.py lines 20-49) fills NaNs with the tile's spatial mean for that time-band. If a whole time-band slice is NaN, it falls back to the band's mean over time. If a band is NaN everywhere, it fills with **raw 0** (line 43). That 0 lands before `normalizing_dict` is applied at inference (inference.py lines 81-84). The same `load_tif` runs for labelled data (`labeled_dataset.py` lines 154, 202) and for inference (`process_test_file`, line 168). The 0 path is a constant, possibly out-of-distribution fill. It only triggers for a band missing across the whole tile, not for one missing month.

**WorldCereal (WorldCereal/worldcereal-classification + WorldCereal/prometheo).** Inputs are monthly or dekadal composites (`preprocessing.py` line 539: `median_compositing` of S2 after the SCL mask). Missing entries are written as `NODATAVALUE=65535` (`train/data.py` line 1201, `datasets.py` line 1089). The prometheo Presto wrapper sets `mask = values == NODATAVALUE` per sensor before normalization (wrapper.py lines 285-324). Training can enable `SensorMaskingConfig`, set in `train/data.py` lines 758-766: S2 per-timestep cloud dropout 0.25, contiguous S2 cloud blocks of 2-5 steps, and S1/meteo dropout, implemented in `_apply_masking` (`datasets.py` lines 1495-1560). Inference sets disabled modalities and NaNs to `NODATA_VALUE` (`openeo/inference.py` lines 1469-1536), so they reach the model as masked tokens. This is the only codebase that both masks missing timesteps and simulates them in supervised training.

**R `sits` (e-sensing/sits).** `impute_fn = impute_linear()` is the default in `sits_get_data`, `sits_classify`, `sits_reduce` and `sits_segmentation` (for example `sits_get_data.R` line 168, `sits_classify.R` line 169). During classification, cloud-masked pixels become NA and are imputed before the model sees them (`api_classify.R` lines 459-466). `interp_linear.cpp` interpolates interior gaps and copies the nearest valid value into leading and trailing NAs. Normalization by training statistics happens inside the trained model closure, after imputation. Training samples go through the same imputation in `sits_get_data`.

**eo-learn (sentinel-hub/eo-learn), land-cover example.** The notebook builds `IS_VALID = IS_DATA & ~CLM` (cell 11). It drops frames with 80% or less valid coverage (`SimpleFilterTask`, cell 42), then runs `LinearInterpolationTask` with `mask_feature=IS_VALID` onto a fixed 15-day grid. Values that cannot be interpolated get `unknown_value`, which defaults to NaN (interpolation.py lines 135, 413). LightGBM handles those natively. The same patches are used for prediction (cell 70, `PredictPatchTask`). This is a land-cover example rather than a crop-specific pipeline.

**TSViT (michaeltrs/DeepSatModels).** The PASTIS transform order is `ToTensor`, `Normalize` (fixed per-fold mean/std), `TileDates`, then `CutOrPad(max_seq_len=60, from_start=True)` (data_transforms.py lines 21-30). `pad_or_cut` appends zero frames after normalization (lines 282-300). The temporal transformer receives no padding mask: `seq_lengths` is computed but not used by the TSViT forward pass (not verified for every TSViT variant). Training and evaluation use the same transform. PASTIS sequence lengths vary, so zero frames appear in training as well. This is a constant fill without a mask, but it is not train/test-inconsistent.

**Sen4AgriNet (Orion-AI-Lab/S4A-Models).** `get_medians` bins observations by `group_freq='1MS'` and takes the median per month (`PAD_dataset.py` lines 292-299). It resamples so that empty months become NaN, then calls `interpolate_na(method='linear', fill_value='extrapolate')` (lines 301-307). Hollstein cloud masks are computed on the medians and returned as an output (lines 510-515). They are not used to remove observations before the median. Every split uses the same procedure.

**EuroCropsML (dida-do/eurocropsml).** Preprocessing removes `-999` padding rows (`preprocess.py` lines 113-119). It also removes cloudy S2 observations with a B4-reflectance cloud probability (lines 122-162, applied at lines 211-212). Data are scaled to (0,1] with an epsilon offset (`dataset.py` lines 165-174), so a 0.0 pad cannot be confused with real data. `config.py` lines 153-157 warn about this when normalization is disabled. The collate function in `base.py` (lines 94-155) builds `pad_mask` from the pad value and combines it with any augmentation `mask`. I did not trace where augmentation masks are produced, since the models live in a separate code path.

**AI4Food starter pack (AI4EO/tum-planet-radearth-ai4food-challenge).** This is the starter pack for the challenge whose South Africa track is our dataset. `S2Reader` loads cloud probability (`clp.npy`) and keeps it as a separate `cloud_stack`. It is concatenated to the bands only when `include_cloud=True`, which is off by default (lines 27, 118-120). Reflectance is scaled by 1e-4 and z-normalized with fixed constants plus jitter (`data_transform.py` lines 62-67). Cloudy S2 observations therefore enter the baseline models as raw values. The notebook describes Planet Fusion as a clean, gap-filled daily product, so for that sensor gaps are removed upstream.

**torchgeo PASTIS (microsoft/torchgeo).** The `PASTIS` dataset returns the raw `(T, C, H, W)` array without padding, masks or dates. Nodata handling is left to the user. I read only the main branch through raw GitHub and did not pin a commit.

**Not audited.** MCTNet and the code for Che et al. 2024 ("linear interpolation helps little") were not searched for or checked, so their status is not verified. Six of the 17 audited codebases come from two groups (Sainte Fare Garnot et al.: PSE-TAE, L-TAE, U-TAE; NASA Harvest: Presto, CropHarvest, OpenMapFlow), and TimeMatch reuses the PSE-TAE model code, so the sample is not independent.
